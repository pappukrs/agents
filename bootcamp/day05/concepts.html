2 · Your loop is already a graph

LangGraph doesn't add intelligence. It adds structure.

Look at Day 2's run_agent: call the model, maybe run tools, go back. That's two boxes and three arrows. LangGraph makes those boxes and arrows explicit, and in return gives you saving, pausing and resuming for free.

Day 2 · loop.py 
for _ in range(max_steps):
    res = llm.chat(contents)   # box: think
    if not res.function_calls: # arrow: END
        return answer
    run the tools              # box: act
    append results             # arrow: back

State lives in local variables. If the process dies, it's gone.

Day 5 · graph_agent.py

State lives in a dict that's saved after every box. Kill the process and pick up where it stopped.

One sentence to rememberA LangGraph app = a state dict + nodes that update it + edges that pick the next node, compiled into something you .invoke().
3 · State and reducers

Nodes don't edit state. They return updates, and reducers merge them.

A node returns a partial dict, only the keys it changed. For each key, LangGraph decides how to merge: by default the new value replaces the old one. With a reducer like operator.add, it's appended. Toggle the reducer and watch the result.

class AgentState(TypedDict):
    contents: Annotated[list[dict], operator.add]   # reducer: append
    steps: int                                     # no reducer: replace
    answer: str

JS analogy: a Redux reducer per keyThink of each key having its own reducer: contents: (old, upd) => [...old, ...upd], everything else (old, upd) => upd. The node is like an action creator: it only describes the change.

  
State must be saveableThe checkpointer serialises state after every node. So store Gemini messages as plain dicts (content.model_dump(exclude_none=True)) and rebuild them with types.Content.model_validate(d) before calling llm.chat. Plain data in state, no clients, no open files.






  
4 · Nodes and edges

  
A node is a plain function: state → update

  
No base classes. Each node reads what it needs from state and returns what changed. Edges are wired up once, in a builder.


from langgraph.graph import StateGraph, START, END

def think(state: AgentState) -> dict:
    res, stats = llm.chat(to_contents(state["contents"]), tools=DECLS, system=SYSTEM)
    return {"contents": [dump(res.candidates[0].content)],   # appended (reducer)
            "steps": state["steps"] + 1,                     # replaced
            "answer": stats.text}

def act(state: AgentState) -> dict:
    calls = last_calls(state)                                # function_calls in the last model turn
    parts = [function_response(c, run_tool(c["name"], c["args"])) for c in calls]
    return {"contents": [{"role": "user", "parts": parts}]}

builder = StateGraph(AgentState)
builder.add_node("think", think)
builder.add_node("act", act)
builder.add_edge(START, "think")                 # always
builder.add_conditional_edges("think", route, ["act", END])   # decided by route()
builder.add_edge("act", "think")                 # always go back
graph = builder.compile()

  

    
Same tools
run_tool and the @tool registry from Day 2 are reused unchanged. Errors are still observations.

    
Same model call
think wraps Day 2's llm.chat(). No LangChain chat model needed.

    
New: wiring
The for loop and if become add_edge and add_conditional_edges.

  






  
5 · Conditional edges

  
A router function looks at state and names the next node

  
This is the if from your loop, moved into a function. Flip the conditions and see which arrow route() picks.

  

    


def route(state) -> Literal["act", "approve", "__end__"]:
    calls = last_calls(state)
    if not calls:                    return END
    if state["steps"] >= MAX_STEPS:  return END
    if any(c["name"] in DANGEROUS for c in calls):
        return "approve"
    return "act"

      

        
        
        
      

      

    

    

  

  
Why the Literal[...] return type?It documents the possible destinations, like a TS union return type. The third argument of add_conditional_edges (["act", "approve", END]) tells LangGraph the same thing, so it can draw the graph and fail early on typos.

from langgraph.checkpoint.sqlite import SqliteSaver

with SqliteSaver.from_conn_string("checkpoints.db") as saver:
    graph = builder.compile(checkpointer=saver)
    config = {"configurable": {"thread_id": "demo1"}}
    graph.invoke({"contents": [user(q)], "steps": 0, "answer": ""}, config)   # new run
    graph.invoke(None, config)                     # resume: continue from the last checkpoint
    graph.get_state(config).next                    # which node runs next, e.g. ('act',)

  

    
CheckpointerWhere state livesSurvives a crash?Use for

    
nonenowhereNo. No interrupts eitherSimple one-shot graphs

    
MemorySaverPython dict in this processNo (dies with the process)Tests, notebooks, pause/resume in one run

    
SqliteSavercheckpoints.db fileYesHackathon demos, CLI tools

  

  
Resume re-runs the step that was interruptedOnly finished steps are saved. If the process dies inside act, resuming runs act again from the start. Tools with side effects (sending email, deleting files) should be safe to run twice, or be behind an approval.






  
7 · Human approval with interrupt()

  
Pause the graph, ask a person, continue with their answer

  
interrupt(value) stops the run and saves state. Your code shows value to a human. Later, invoke(Command(resume=answer), config) continues, and interrupt() returns that answer. Step through it.

from langgraph.types import interrupt, Command

def approve(state: AgentState) -> dict:
    calls = last_calls(state)
    decision = interrupt({"calls": calls})        # pauses here the first time
    if str(decision).lower().startswith("y"):
        return {"approved": True}
    rejected = [function_response(c, {"error": "Rejected by the user. Do not retry."}) for c in calls]
    return {"approved": False, "contents": [{"role": "user", "parts": rejected}]}

builder.add_conditional_edges("approve", lambda s: "act" if s["approved"] else "think", ["act", "think"])

  

    
The node re-runs on resume
LangGraph doesn't freeze the Python function mid-line. On resume it runs approve again from the top, and this time interrupt() returns the answer instead of pausing. So keep code before interrupt() free of side effects.

    
Rejection = an observation
Same idea as Day 2: a "no" goes back to the model as {"error": "Rejected by the user"}, so it can explain or choose another way. Nothing crashes.

  

  
Interrupts need a checkpointerWithout one there's nowhere to save the paused state, so interrupt() can't work. MemorySaver is enough inside one process; SqliteSaver lets the human answer after a restart.

9 · TypedDict and Annotated

  
A dict with a declared shape, plus metadata on a type

  
LangGraph state is usually a TypedDict: at runtime it's a normal dict, but type checkers and LangGraph know its keys.

  

    
Python (state.py)
import operator
from typing import Annotated, TypedDict

class AgentState(TypedDict):
    contents: Annotated[list[dict], operator.add]
    steps: int
    answer: str
    approved: bool

s: AgentState = {"contents": [], "steps": 0,
                 "answer": "", "approved": False}
s["steps"]      # dict access, not s.steps

    
JS / TS
type AgentState = {
  contents: Record<string, unknown>[];
  steps: number;
  answer: string;
  approved: boolean;
};
// TS has no slot for "how to merge this key".
// LangGraph JS uses Annotation.Root({...})
// with a reducer per key instead.

  

  

    
PythonWhat it meansJS feel

    
Annotated[T, x]Type T, plus extra info x that tools can read at runtimea type with a decorator attached

    
operator.addThe + operator as a function: add(a, b) == a + b; for lists, that's concatenation(a, b) => [...a, ...b]

    
TypedDict vs @dataclassTypedDict = plain dict with known keys; dataclass = object with attributesobject literal type vs class

  






  
10 · Partial updates and spreading

  
Return only what changed

  

    
Python
# a node returns a partial update
return {"steps": state["steps"] + 1}

# merging dicts yourself (tests, helpers)
new = {**state, "steps": 3}
new = state | {"steps": 3}      # 3.9+

# list concat, what operator.add does
[1, 2] + [3]                  # [1, 2, 3]

    
JS / TS
// React setState / Redux style
return { steps: state.steps + 1 };

// spreading
const next = { ...state, steps: 3 };


// array concat
[1, 2].concat([3]);  // or [...a, ...b]

  

  
Gotcha: [1, 2] + 3 is a TypeError in Python (JS would give the string "1,23"). That's why a node must return {"contents": [msg]}, a list, not a single message.

  
lambda = a one-expression arrow function

  

    
Python
lambda s: "act" if s["approved"] else "think"

    
JS / TS
(s) => (s.approved ? "act" : "think")

  

  
Python's ternary reads A if cond else B: value first, condition in the middle.

Open, use, always close

    graph = build_graph(saver)

JS / TS
const saver = openSaver("checkpoints.db");
try {
  const graph = buildGraph(saver);
} finally {
  saver.close();
}
// TS 5.2+: `using saver = ...` is the same idea

  

  
The config dict is how you pick the thread

  

    
Python
config = {"configurable": {"thread_id": args.thread}}
graph.invoke(inputs, config)
graph.get_state(config).values["steps"]

    
JS / TS
const config = { configurable: { thread_id: args.thread } };
await graph.invoke(inputs, config);
(await graph.getState(config)).values.steps;

  

  
Same thread_id = same conversation, continued. New thread_id = fresh start. Think of it like a session id.

  
Python is sync hereDay 5 uses graph.invoke(), which blocks like a normal function call. LangGraph also has await graph.ainvoke() for async code (Day 4's asyncio). Pick one style per program.

13 · Self-check

  
Answer out loud before opening

  
A node returns {"contents": [msg]}. Why doesn't that wipe the old messages?Because contents is Annotated[list, operator.add]: the reducer appends the update to the old list. Keys without a reducer (like steps) are replaced.

  
What does a router function return, and where is it registered?The name of the next node (or END). It's passed to builder.add_conditional_edges("think", route, ["act", "approve", END]).

  
When exactly is a checkpoint written?After each step (each node that finishes), under the thread_id from the config. A node that was running when the process died isn't saved, so it runs again on resume.

  
How do you resume a run after a crash?Same checkpointer (e.g. the same checkpoints.db), same thread_id, then graph.invoke(None, config). graph.get_state(config).next tells you which node will run.

  
Why does MemorySaver not survive Ctrl+C?It keeps checkpoints in a Python dict inside the process. When the process dies, the dict is gone. SqliteSaver writes to a file.

  
After Command(resume="y"), does approve continue from the line after interrupt()?No. It runs again from the top; this time interrupt() returns "y" instead of pausing. Code before interrupt() must be safe to run twice.

  
The human says "n". What does the model see?A function response {"error": "Rejected by the user. Do not retry."} for each pending call, then think runs again so the model can explain. Same "errors are observations" rule as Day 2.

  
The hackathon task is "answer questions over these CSVs with tools". Custom loop or LangGraph?Custom loop. It's one agent calling tools until done: no branching state, no human approval, no long pauses. LangGraph would add setup and debugging time for nothing.
