2 · Hosted vs open models

Rent a model through an API, or run the weights yourself

"Open" (open-weight) means you can download the model and run it on your own machine. "Hosted" means you call someone else's servers. For a one-day hackathon the answer is almost always hosted, but you should know why.

Hosted API

Gemini, Claude, GPT…

  • Zero setup: a key and an HTTP call
  • Strongest models, long context, tool calling built in
  • You pay per token (check the pricing page)
  • Risks: rate limits (429), outages, needs internet
  • Your data goes to the provider
Open weights

Llama, Qwen, Mistral, Gemma… (run via Ollama, vLLM)

  • Runs offline, data stays on your machine
  • No per-token bill, but you need the hardware (GPU/RAM)
  • Smaller ones fit a laptop, but are weaker at tool calling
  • You can fine-tune them (LoRA, section 4)
  • Setup and download time you don't have on the day
Hackathon rule of thumbHosted model as primary, a second hosted provider as backup (section 6). An open model on your laptop is only worth it if the venue Wi-Fi might die, or if the problem explicitly says "no external APIs".
3 · Prompting vs RAG vs fine-tuning

Fix the cheapest thing first

When the agent gets something wrong, there are three levers. They differ hugely in effort. Walk the tree, or pick a preset situation.

LeverWhat it changesEffortGood for
PromptingThe instructions and examples in the requestMinutesFormat, tone, rules, step order, few-shot examples
RAGWhat facts are in the context (Day 3)HoursPrivate or changing knowledge, citations, "I don't know"
Fine-tuningThe model's weightsDays + data + GPUA narrow, repeated behaviour you can show with many examples; making a small model act like a big one
Fine-tuning does not teach facts wellIt shapes behaviour (style, format, a narrow skill). For "know our documents", use RAG. And not on hackathon day: no time to collect data, train and evaluate.
4 · LoRA and QLoRA (concept only)

Don't retrain the whole matrix. Train a tiny "patch" next to it.

A model is mostly big weight matrices. Full fine-tuning updates all of them. LoRA freezes them and learns a small low-rank update B × A that is added on top. Drag the sliders.

full fine-tune: d × d
LoRA: 2 × d × r
of the parameters

Per matrix. A real model has hundreds of these; LoRA is usually applied to a subset of them (e.g. the attention projections).

QLoRA = LoRA on a 4-bit base model

The frozen W is stored in 4-bit instead of 16-bit, so it takes about a quarter of the memory. The small adapters still train in higher precision. Rough memory for just the weights of a 7B-parameter model:

16-bit (full)
~14 GB
8-bit
~7 GB
4-bit (QLoRA base)
~3.5 GB

7B params × 2 bytes ≈ 14 GB; × 0.5 byte ≈ 3.5 GB. Training also needs memory for activations and optimizer state, so real numbers are higher.

What to say if a judge asks"We'd fine-tune only with a few hundred good examples of a narrow behaviour that prompting and RAG couldn't fix. We'd use QLoRA on an open model so it fits one GPU, and compare against the prompted baseline on the same eval set."

# llm.py (planned): try providers in order, fall back only on errors worth falling back on
def chat(messages, *, tools=None, **kw) -> Reply:
    errors = []
    for provider in provider_order():          # e.g. [gemini, anthropic]
        try:
            return provider.chat(messages, tools=tools, **kw)
        except LLMError as e:
            if not e.retryable:                    # 400: our bug, don't hide it
                raise
            errors.append(f"{provider.name}: {e}")
    raise LLMError("all providers failed: " + "; ".join(errors))
The hidden cost: message formats differDay 2's loop stores Gemini types.Content objects. Anthropic and OpenAI use different shapes for tool calls and tool results. So the switch needs one neutral format (Message, ToolCall, Reply) and a small adapter per provider. Test the backup path before the event, with a fake 429.

There are no event handlers or components. Streamlit runs app.py from line 1 to the end, draws whatever it hits, and on any interaction does it all again. Click the button and watch.

Python · app.py
import streamlit as st

if "messages" not in st.session_state:
    st.session_state.messages = []

for m in st.session_state.messages:    # redraw history
    with st.chat_message(m["role"]):
        st.markdown(m["content"])

if prompt := st.chat_input("Ask the agent"):
    st.session_state.messages.append(
        {"role": "user", "content": prompt})
    ...  # run the agent, append the answer
React
function Chat() {
  const [messages, setMessages] = useState([]);

  return (<>
    {messages.map((m, i) =>
      <Bubble key={i} role={m.role}>{m.content}</Bubble>)}
    <ChatInput onSubmit={(prompt) =>
      setMessages([...messages,
        { role: "user", content: prompt }])} />
  </>);
}

:= is the "walrus" operator: assign and test in one go. if prompt := st.chat_input(): is like const prompt = chatInput(); if (prompt) {…}.

Two classic Streamlit bugs1. Keeping history in a normal variable: it resets to [] on every rerun (the left counter above). 2. Creating the LLM client or loading the index at the top of the script without @st.cache_resource: it rebuilds on every keystroke-triggered rerun.
9 · A provider interface

Protocol is Python's TypeScript interface

Each provider class just needs the right method. It doesn't have to inherit from anything, same as TS structural typing.

Python · providers.py
from typing import Protocol

class Provider(Protocol):
    name: str
    def chat(self, messages: list[Message], *,
             tools: list[dict] | None = None) -> Reply: ...

class GeminiProvider:          # no "implements" needed
    name = "gemini"
    def chat(self, messages, *, tools=None) -> Reply:
        ...  # convert Message → types.Content, call, convert back
TS
interface Provider {
  name: string;
  chat(messages: Message[],
       opts?: { tools?: ToolDecl[] }): Promise<Reply>;
}

class GeminiProvider implements Provider {
  name = "gemini";
  async chat(messages, opts) { ... }
}
Choosing from an env var
Python
PROVIDERS = {"gemini": GeminiProvider, "anthropic": AnthropicProvider}

def provider_order() -> list[Provider]:
    first = os.getenv("LLM_PROVIDER", "gemini")
    rest = [n for n in PROVIDERS if n != first]
    return [PROVIDERS[n]() for n in [first, *rest]]
JS
const PROVIDERS = { gemini: GeminiProvider, anthropic: AnthropicProvider };

function providerOrder() {
  const first = process.env.LLM_PROVIDER ?? "gemini";
  const rest = Object.keys(PROVIDERS).filter((n) => n !== first);
  return [first, ...rest].map((n) => new PROVIDERS[n]());
}

[first, *rest] is Python's spread: same as [first, ...rest].

10 · Callbacks and with blocks

Stream each agent step into the UI as it happens

run_agent gets an on_step callback. The app passes a function that writes into an st.status box, so the trace appears live instead of after the run.

Python · app.py
with st.chat_message("assistant"):
    with st.status("Thinking…", expanded=True) as box:
        result = run_agent(
            prompt,
            on_step=lambda s: box.write(Trace.format(s)),
        )
        box.update(label=f"Done in {len(result.trace.steps)} steps",
                   state="complete", expanded=False)
    st.markdown(result.answer)
JS (same idea)
const box = ui.status("Thinking…");
const result = await runAgent(prompt, {
  onStep: (s) => box.write(formatStep(s)),
});
box.update({ label: `Done in ${result.trace.steps.length} steps`,
             state: "complete" });
ui.markdown(result.answer);

lambda s: … is a one-expression arrow function, (s) => …. For more than one line, define a normal def and pass its name.

with = "everything inside goes in here"A context manager runs setup on entry and cleanup on exit (like try/finally). Streamlit uses it for layout: anything drawn inside with st.chat_message("assistant"): appears inside that bubble. Same as nesting children in JSX.

12 · Self-check

Answer out loud before opening

The agent gets facts about your company's docs wrong. Prompt, RAG or fine-tune?RAG. The model can't know private facts; put them in the context with retrieval and cite them. Fine-tuning is poor at adding facts.
Why does LoRA train so few parameters?It freezes the big d×d matrix and learns two thin ones, B (d×r) and A (r×d), with small r. That's 2·d·r numbers instead of d². With d=4096, r=8 it's well under 1% of the matrix.
What does the Q in QLoRA add?The frozen base model is loaded in 4-bit, about a quarter of the 16-bit memory, so bigger models fit on one GPU. The adapters still train in higher precision.
Model A passes 9/10 in 2.1s, model B passes 7/10 in 0.8s. Which do you demo?Usually A: a fast wrong answer is still wrong. Set a minimum pass rate first, then compare speed and cost among what's left. Say the numbers out loud in the pitch.
Gemini returns 400. Should the app fall back to the backup provider?No. 400 means our request is wrong (bad schema, bad params). The backup would likely fail too and hide the bug. Fall back on 429 / 5xx / timeouts only.
You keep the chat history in messages = [] at the top of app.py. What happens?Every interaction reruns the script, so it resets to empty and the old messages disappear. Use st.session_state.messages.
Why wrap the client / RAG index creation in @st.cache_resource?Otherwise it's rebuilt on every rerun (every message). Cached, it's created once per server process and reused.
How does the trace show up live instead of after the answer?run_agent calls on_step(step) after each LLM or tool step; the app's callback writes it into an st.status box that is already on screen.
