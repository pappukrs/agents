2 · What RAG is

Two phases: index once, search on every question

The model has never seen your files, and they're too big to paste whole into every prompt. So you find the relevant bits first, then pass only those.

One sentence to rememberRAG = search first, then answer only from what you found. The model's job changes from "remember facts" to "read these passages and summarise them honestly".
JS analogyIt's a search index like Algolia or Elasticsearch, but the "match" is by meaning, not by keywords. "Can I get my money back?" finds a passage that says "refunds are issued…" even though no word overlaps.
3 · Embeddings

An embedding turns text into a direction in space

Texts with similar meaning point in similar directions. Real embeddings from gemini-embedding-001 have 3072 numbers (we'll ask for 768). Here's a toy version with 2, so you can see it. Pick a question, or click anywhere on the map to place your own.

    4 · Cosine similarity

    "How much do two arrows point the same way?"

    Cosine = dot product divided by both lengths. 1 = same direction, 0 = unrelated, −1 = opposite. If you normalise every vector to length 1 once, at ingest time, cosine becomes just a dot product.

    Python + numpy (planned rag.py)
    import numpy as np

def normalize(m: np.ndarray) -> np.ndarray:
    return m / np.linalg.norm(m, axis=-1, keepdims=True)

# vectors: (n_chunks, 768), already normalised
# q:       (768,),         normalised
scores = vectors @ q     # ALL cosines in one line
    JS / TS
    const dot = (a, b) => a.reduce((s, x, i) => s + x * b[i], 0);
const norm = (a) => Math.sqrt(dot(a, a));
const cosine = (a, b) => dot(a, b) / (norm(a) * norm(b));

const scores = vectors.map((v) => cosine(v, q));
// a loop in JS; numpy does it in C, ~100x faster
    Normalise when you shrinkGemini's full 3072-number vectors come back normalised. When you ask for fewer with output_dimensionality=768 they don't, so normalise them yourself or your "cosine" scores will be off.
    5 · Chunking

    Cut documents into pieces small enough to be specific

    One vector per whole file is too blurry: a 10-page policy "means" everything at once. Tiny chunks lose context. Overlap stops a sentence from being cut in half at a boundary. Drag the sliders; the highlighted text is repeated from the previous chunk.

    # planned rag.py: the same logic as this demo
def chunk_text(text: str, size: int = 800, overlap: int = 150) -> list[str]:
    step = size - overlap
    chunks = []
    for start in range(0, len(text), step):
        chunks.append(text[start:start + size])
        if start + size >= len(text):
            break
    return chunks
    Too small (~100 chars)Good start (~500–1000 chars, 10–20% overlap)Too big (whole file)
    Precise match, but the chunk lacks context: "It is 30 days." What is?One idea per chunk, with enough surrounding words to make sense alone.Blurry vector; also wastes context tokens when it's put in the prompt.
    Better splitting, laterSplitting on headings and paragraphs (Markdown ## , blank lines) beats raw characters. Start with characters because it's 8 lines and always works; improve only if the eval says so.
    6 · Top-k + threshold

    Keep the best k chunks, but only if they're actually good

    Top-k always returns something, even for a question the docs don't cover. The threshold is what lets the agent say "I don't know". These scores are realistic for gemini-embedding-001.

    There is no universal thresholdIt depends on the embedding model, the chunk size and your documents. Pick it from data: run your 10 questions, look at the best score for the answerable vs unanswerable ones, and put the line between them. That's a Test-block task today.
    7 · Reranking

    Cheap search for many, careful check for a few

    Cosine is fast but rough: it compares meanings, not "does this passage answer the question?". A reranker looks at each (question, chunk) pair and scores real relevance. It's slower, so run it only on the top ~10.

    Question: "Does the warranty cover water damage?"
    Stage 1 · cosine top-6
      Stage 2 · LLM rerank, keep 2

        How to rerank with what you have
        Day 1's generate_structured() with a schema like {"scores": [{"id": str, "relevance": int 0–10}]}, all candidates in one call. One extra LLM call per search.
        When to bother
        Only if the eval shows right chunks ranked low. On a hackathon day, start without it. It's an upgrade, not a requirement.

        # planned rag.py: the tool the model sees
@tool
def search_docs(query: str, k: int = 4) -> dict:
    """Search the provided documents. Returns the most relevant passages with ids to cite.
    If 'hits' is empty, the documents do not answer the question: say so, don't guess.

    Args:
        query: what to look for, in your own words. Rephrase and search again if results are weak.
        k: how many passages to return (1-8).
    """
    hits = search(query, k=min(k, 8), min_score=MIN_SCORE)
    if not hits:
        return {"hits": [], "note": f"No passage scored above {MIN_SCORE}."}
    return {"hits": [{"id": h.id, "score": round(h.score, 2), "text": h.text} for h in hits]}

        12 · Self-check

        Answer out loud before opening

        Why not paste every document into the prompt instead of doing RAG?It may not fit the context window; when it does, every question pays for all those input tokens, and models get worse at finding one fact in a huge prompt. RAG sends only the few passages that matter.
        What does cosine similarity measure, and why can it become a plain dot product?How much two vectors point the same way, ignoring their length. If every vector is normalised to length 1, the denominator is 1, so cosine = dot product. That's why we normalise at ingest.
        Why two task types, RETRIEVAL_DOCUMENT and RETRIEVAL_QUERY?Questions and passages are written differently (short question vs long statement). Gemini produces slightly different vectors for each role so that a question lands near the passage that answers it.
        What goes wrong with chunks that are too big? Too small?Too big: the vector is a blur of many topics, and each hit wastes context. Too small: chunks lose context ("It is 30 days." What is?). Overlap keeps sentences at boundaries intact.
        Top-k always returns k results. How does the agent ever say "I don't know"?The score threshold in search() drops weak matches. If nothing passes, the tool returns empty hits plus a note, and the prompt says: no hits → say the documents don't cover it.
        How do you pick the threshold?From data: run the eval questions, compare the best score for answerable vs unanswerable ones, and set the line between them. It's specific to the model, chunk size and documents.
        What is reranking, and when would you skip it?A second, slower pass that scores each (question, chunk) pair for real relevance, usually with an LLM, on the top ~10 cosine hits. Skip it until the eval shows the right chunk is retrieved but ranked too low.
        The model cites pricing.md#3 but search never returned it. Which layer catches that?Code: check_citations() compares every cited id against the ids the tools actually returned in this run, and fails the answer if any are made up.
